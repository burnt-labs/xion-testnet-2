# Xion v33 Release Notes

## Overview

Xion v33 is a maintenance release on top of v32 (Fermi). xion-testnet-2 runs the release candidate `v33.0.0-rc2`, tagged on [`eb86339`](https://github.com/burnt-labs/xion/commit/eb863391517e129ae2b5979f582b04b81e9bed69); xion-mainnet-1 follows with `v33.0.0`. It fixes a feegrant EndBlocker failure that a single expiring legacy fee allowance could trigger on SDK v0.55, and makes the 1s `consensus.timeout_commit` default apply.

## Upgrade

- **Upgrade name**: `v33` (`UpgradeName` in `app/upgrades.go`)
- **Upgrade height**: [19487000](https://www.mintscan.io/verona-testnet/block/19487000) (expected around 2026-11-03 02:00 UTC, 20:00 CT on 2026-11-02; recomputed right before the proposal is submitted)
- **Proposal**: [067](../proposals/067-upgrade-v33.json), expedited (1 h vote)
- **Binaries**: [`releases/v33.json`](../releases/v33.json)

## What's Changed

- fix(cmd): make the 1s `consensus.timeout_commit` default apply ([#696](https://github.com/burnt-labs/xion/pull/696), ENG-2029)
- feat(app): rewrite legacy feegrant queue values in the v33 upgrade ([#703](https://github.com/burnt-labs/xion/pull/703))
- fix(app): drop the v32 height-gated feegrant queue rewrite from release/v33 ([#711](https://github.com/burnt-labs/xion/pull/711))
- ci: finish Linux release orchestration migration to Ubicloud ([#701](https://github.com/burnt-labs/xion/pull/701), DO-556)

Full changelog: https://github.com/burnt-labs/xion/compare/v32.1.0-rc2...v33.0.0-rc2

### Dependencies

Unchanged from v32: Cosmos SDK v0.55, CometBFT v0.40, ibc-go v11, wasmd v0.70 fork.

### Upgrade Handler

- Upgrade name `v33`.
- No stores are added, renamed or deleted; v32 already removed the retired module stores.
- Runs the standard module migrations.
- Rewrites the fee allowance queue entries that `cosmossdk.io/x/feegrant` stored with an empty value to the `BoolValue` encoding the SDK v0.55 feegrant keeper reads. Without it, `RemoveExpiredAllowances` fails the feegrant EndBlocker as soon as one legacy entry expires. Entries that already hold a value are left alone, so the rewrite is idempotent.
- The legacy `x/params` store stays mounted; the globalfee and jwk migrations that read it ran in v32.

## Node Operators

- With Cosmovisor, place the binary at `upgrades/v33/bin/xiond`; `releases/v33.json` lists the binaries with checksums.
- Existing `config.toml`, `app.toml` and data directories open unchanged. There is no DB migration step.
- `consensus.timeout_commit` defaults to `1s` on freshly generated configs; existing configs keep their value.

## Integrators

No API, state-encoding or signing changes versus v32.
